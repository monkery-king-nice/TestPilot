# 曾炜毅：后端基础与数据交付

## 完成内容

依据六人开发包中“4-曾炜毅-AI任务.md”，本次实现 FR-01、02、03 中共同接口约定的部分。

- FastAPI共享入口、SQLite连接与事务、自动建表、统一字符串detail错误响应。
- 项目创建与列表，需求创建/列表/修改，端点登记与列表，环境配置写入/读取。
- 需求每次修改版本加一并保留原文历史；需求与接口当前版本查询及版本不匹配拒绝。
- 按project_id校验引用归属，跨项目修改和内部查询均拒绝。
- 环境公开响应只返回已配置字段名，提供仅服务端使用的read_environment函数。
- 提供Agent的load_text适配器，明确路由注册入口，未合入模块不会被自动导入。
- 启动命令、全组接口契约、事务与数据库访问样例、前端代理说明、可重复验收脚本。

代码主要在 `backend/app/main.py`、`backend/app/core/`、`backend/app/modules/projects/`。
开发分支 `feature/backend-project-data`，已同步 `origin/main` 的 `95fd712`（包含队友已合入的需求澄清及执行器模块），并在共享后端注册需求澄清路由、接入真实需求数据库。
交付范围与运行方式见本文件及根README；提交通过独立分支和PR交接。

## 实测结果

环境：Windows、Python 3.13.15、pytest 8.4.2，运行依赖精确版本见 `backend/requirements.txt`，完整测试环境见 `backend/requirements-lock.txt`；pytest继续遵守执行器模块的8.x约定。

```text

python -m ruff check backend/app/core backend/app/modules/projects backend/app/main.py backend/scripts backend/tests/test_projects.py
All checks passed!

python -m ruff format --check backend/app/core backend/app/modules/projects backend/app/main.py backend/scripts backend/tests/test_projects.py
11 files already formatted

python -m pip check

python backend/scripts/verify_project_data.py --output docs/evidence/project-data-http.json
PASS: 7 real HTTP acceptance checks (including process restart)
```

自动化测试中的数据库都是独立临时文件。61项测试包含42项本模块/接入测试、6项主分支已有Agent测试和13项已有执行器测试，覆盖正常录入、需求历史/并发修订、旧版本拒绝、项目隔离、环境更新与不回传、无效输入、事务回滚、外键、接口文档及错误结构；本模块新增需求澄清读取最新正文、跨项目拒绝且不调用模型、模型错误后基础数据仍可用三个接入测试。Agent provider使用明确的测试替身，未做真实模型效果评估。
第三方警告来自当前Starlette测试客户端对httpx的弃用提示，测试均通过。
首次交付已在全新虚拟环境验证39项基础测试及7项真实HTTP验收；同步最新main并接入Agent后，重新验证61项测试及真实HTTP验收。
另7项验收使用独立uvicorn进程和真实本机HTTP，终止首个进程后再启动第二个进程读取同一SQLite文件；不是用内存状态模拟重启。详细脱敏输出见 [HTTP验收证据](evidence/project-data-http.json)。

## 站会可演示

按根README启动后打开 `http://127.0.0.1:8000/docs`：

1. POST /api/projects 创建项目，展示201和id；GET展示项目列表。
2. 创建需求后PATCH补充正文，展示version从1变2。
3. 登记POST /auth/login和GET /me。
4. 配置环境后GET，仅展示configured_keys，没有username/password值。
5. 在另一项目下尝试PATCH同一需求，返回404。
6. 重启服务，再读取原项目数据，验证持久化。

保留创建成功、版本递增、跨项目拒绝和不含环境值的GET响应；可直接使用验收JSON作为记录。
截图/录屏时不要展示环境PUT的真实凭证或终端中的密钥。
