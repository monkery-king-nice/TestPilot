# 示例被测项目：一箭又一箭

这个目录里放的是**被 TestPilot 测的那个小游戏**，不是平台本身。它对应整个流程里「给 AI 说一句想要什么功能 → AI 做出一个能跑的项目」的那一环。

## 里面有什么

| 文件 | 作用 |
|---|---|
| `一箭又一箭_测试需求简版.zip` | 要上传到平台的项目包，7 KB。包里只有游戏规则代码、一份很简略的功能需求、以及项目自带的接口说明 |
| `arrow_game_http.py` | 把小游戏的规则变成一个真的能发请求的接口，默认监听本机 `18085` 端口 |

需求文档故意写得很简略，只有六句大白话：点箭头、被挡算失误、清空算过关、3 次机会、能重开。**没说**点空格怎么办、挡路看多远、过关后有没有下一关。这些是 AI 做项目时自己拍板的，正好留给平台用大白话追问出来，让提需求的人确认「这是不是我本来想要的」。

## 第一步：把小游戏接口跑起来

在**仓库根目录**开一个 PowerShell 终端：

```powershell
python examples/arrow-game/arrow_game_http.py examples/arrow-game/一箭又一箭_测试需求简版.zip --port 18085
```

看到 `Arrow Game rules listening on http://127.0.0.1:18085` 就成了，这个终端全程别关。

另开一个终端确认它活着：

```powershell
curl http://127.0.0.1:18085/health
```

应返回 `{"status":"ok","project":"arrow-game"}`。这个服务只认两个地址：`GET /health` 和 `POST /game/move`，别的路径返回 404 是正常的。

## 第二步：启动 TestPilot 平台

见根目录 [README](../../README.md) 的「完整实测演示（推荐路径）」。因为测的是自己的小游戏，用 `-NoDemo` 跳过平台自带的登录演示服务即可，不用设 `DEMO_PASSWORD`。

## 第三步：在页面上从空白走一遍

完整操作见 [从空白到 5 PASS 的操作清单](../../docs/quickstart-demo.md)：新建项目 → 上传这个 ZIP → 登记接口 → 保存需求 → 功能追问 → 补充约定 → 生成并确认用例 → 配环境 → 执行看报告。

## 关于这个精简包

原始作业包有 34 MB，里面绝大部分是 exe、git 历史包和截图，跟接口测试没关系。这个包只保留了平台导入要用的 6 个文件加一份重新生成的 `manifest.json`，共 7 KB。

**游戏规则代码一个字节都没改**：`arrow_game_http.py` 启动时会核对 ZIP 里 `game_logic.py` 的 SHA-256，精简包里的哈希与原项目完全一致；`manifest.json` 已按精简后的文件重新生成。所以测出来的结果和原包是一样的，只是上传更快、仓库更干净。
